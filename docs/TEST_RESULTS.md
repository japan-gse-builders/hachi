## 2. 実機での試験（本番環境 `hachicall-nao`）

試験は Twilio のトライアルアカウントで行い、発信先と親族役は Verified Caller IDs に登録した日本の携帯電話（+81）。試験用の利用者は `infra/seed-test-resident.mjs` で毎回新しく作る。

### 2.1 発信（フェーズ 3）— 成功

| 項目 | 結果 |
|---|---|
| 日時 | 2026-10-02 |
| 流れ | Cloud Scheduler → Cloud Tasks → 発信 API → Twilio → 携帯に着信 → ステータス通知 → Firestore |
| 結果 | 通話状態 `completed`、通話時間 12 秒を記録 |
| 判明したこと | Twilio の API キーは Standard 種別が必要（Restricted で権限なしだと 401 / エラー 8001） |

### 2.2 通話中の急変検知（R1、フェーズ 4・5）— 一部失敗、修正済み（未デプロイ）

| 項目 | 結果 |
|---|---|
| 日時 | 2026-10-02 14:41 JST |
| 利用者の発話（台本） | "I ate mochi and it's in my mouth. I can't breathe." |
| R1 の検知 | 成功。通話中に検知し、R1 ケース（緊急）を作成 |
| 親族への呼び出し電話 | **成功**。親族役の携帯に着信 |
| 利用者への案内と通話の扱い | 成功。終了理由 `emergency`、通話 82 秒・10 往復、録音を保存 |
| 親族への SMS | **失敗**。Hachi 側は検知から 4 秒で送信し「送信済み」と記録したが、Twilio の配信状態は `undelivered`（エラー 30003）で、携帯には届かなかった |
| 職員への通知 | なし。試験では職員の電話番号を利用者と同じにしており、本人への呼び出しは設計上除外している |

**SMS が届かなかった原因と対応**

- 原因（推定）: 親族向け SMS の本文に担当職員の電話番号が入っていた。Twilio の日本向け SMS ガイドラインでは本文に電話番号を入れることが禁止されており、日本の携帯会社で止められたと考えられる。SMS は 2 セグメント（長文）だった
- 対応: 親族向け SMS から電話番号の行を外した（`packages/core/src/notifications.ts`）。メールと音声通報には残す。職員の連絡先はダッシュボードで表示する（FAM-04）。テスト「keeps phone numbers out of family SMS」を追加
- 残作業: Voice Gateway と解析 Worker を再デプロイし、R1 の試験をもう一度行って SMS の着信を確認する
- 補足: Hachi は Twilio が送信を受け付けた時点で「送信済み」と記録しており、携帯への最終的な配信結果は記録していない。配信結果の取り込み（Twilio のステータス通知）は今後の改善点

### 2.3 通話後の解析（R2、フェーズ 6）— 成功

| 項目 | 結果 |
|---|---|
| 日時 | 2026-10-02 16:06 JST（通話 14 往復） |
| 利用者の発話（台本） | 体調 "I'm okay, just a little tired." 食事 "I haven't really eaten for two days. I have no appetite." 雑談 孫の訪問・園芸 |
| 解析 | 成功。モデル `gemini-3.8-flash` |
| 職員向け要約（日本語） | 体調「少し疲れを感じている」、食事「食欲がなく、ここ2日間ほとんど食べていない」、話題「日曜日に孫の訪問予定」「趣味の園芸（バジル栽培）」 |
| 親族向け要約（英語） | 平易な文で体調・食事・話題を記載。引用や話し方の分析は含まない（FAM-03） |
| 食事の記録 | 不十分、2 日間 |
| 次回の通話用の記憶 | 予定「孫が日曜に来る」、好きなこと「園芸」「孫」 |
| R2 のケース | 緊急度「至急」で作成。根拠は利用者の実際の発話 |
| 話し方（R3） | 発話量が足りず評価対象外（設計どおり） |
| 通知 | なし（設計どおり）。「至急」は担当職員だけが対象（NTF-02）で、試験用の職員には SMS・メールの宛先がない。親族には送らない |

**判明した問題と対応**

- デプロイ済みの Voice Gateway が古いイメージのままで、通話終了後の解析依頼が出ていなかった（環境変数だけを追加していた）。新しいコードでビルドし直した（リビジョン `hachi-voice-gateway-00005-x4l`）
- 今回の通話は、解析 Worker の 10 分ごとのスイープが代わりに拾って解析した。依頼が失われても解析されることを本番で確認できた
